Shipping a static launch page should feel boring: green CI, deterministic build output, and a CDN that only updates when you mean it to. Soonex targets GitHub Pages with GitHub Actions as the source, but the same `_site/` artifact works on Netlify, Cloudflare Pages, or any static host.

## Build output

Everything public lives under `_site/` after a full build. HTML is generated by Tableau from Elixir page modules and Markdown posts. CSS comes from Tailwind plus Corex design tokens. JavaScript bundles through esbuild, including skin loaders and cookie consent.

There is no runtime BEAM process in production—only files. That keeps hosting cost at zero and makes rollbacks a matter of redeploying a previous commit.

## Local build sequence

| Step | Command | Output |
| --- | --- | --- |
| Design tokens | `mix corex.design.build` | `assets/corex/` |
| CSS | `mix tailwind default` | `_site/css/site.css` |
| JS | `mix esbuild default` | `_site/js/` |
| Site | `mix tableau.build` | `_site/**/*.html` |

The `mix assets.build` alias runs design, Tailwind, and esbuild together. Run it before `mix tableau.build` in CI so pages reference fresh assets.

## CI checklist

- [x] `mix assets.build` for CSS and JS
- [x] `mix tableau.build` for static HTML
- [x] `mix test` including accessibility audit
- [ ] Your `SOONEX_PUBLIC_URL` on the real origin
- [ ] Custom domain and HTTPS on the host

GitHub Actions should publish Pages **only after** CI succeeds on a push to `main`. Set **Source** to GitHub Actions in the repository settings so a broken push never reaches the public CDN.

> [!TIP]
> Keep CI green before Pages deploys. A failing test is cheaper than a broken launch page indexed by search engines.

## Environment and URLs

Set `SOONEX_PUBLIC_URL` when the origin is real. The demo default is `https://corex-ui.github.io/soonex`. Canonical links, sitemap entries, and Open Graph URLs all read that config value at build time.

If you deploy to a subdirectory, keep the trailing path consistent in config and in your host’s base URL settings. Tableau permalinks are root-relative within `_site/`.

## What we verify in CI

```elixir
defmodule SoonexTest do
  use ExUnit.Case

  test "accessibility audit passes on built HTML" do
    assert File.dir?("_site")
    # a11y_audit scans key routes
  end
end
```

Formatting (`mix format --check-formatted`), compilation with `--warnings-as-errors`, Credo, and tests run on every push. Treat warnings as failures so drift does not accumulate.

## Assets and cache

Fingerprinting is not enabled by default—static filenames like `/css/site.css` are simple for a template. For high-traffic production forks, add cache-busting query strings or content hashes in your host config.

Images ship from `extra/images/` into `_site/images/`. Optimise hero and cover photos before commit; the build does not compress JPEGs for you.

## Rollback plan

Because output is static, rollback is:

1. Revert or fix the commit on `main`
2. Let CI rebuild and redeploy
3. Purge CDN cache if your host caches aggressively

Keep launch-day changes small. Prefer copy and image swaps over structural edits unless you have rehearsed the build locally.
